## Storage and operational boundaries

See [control-state migration and recovery](control-state-sqlite-2026-10-29.md).
Stop the old daemon before upgrading; the legacy JSON is preserved and changed or
malformed legacy sources refuse access. Backups must include encryption keys and
use stopped-daemon copies or SQLite backup semantics for the live database.

New storage tests cover exact/idempotent migration, malformed and changed-source
refusal, nested rollback, process death after SQL flush, concurrent writers,
portable database backup and indexed I/O. An 8,000-job fixture at offset 4,000 and
limit 25 decoded 25 records, used about 136 KiB traced selection memory and took
about 4–6 ms locally. One nested job mutation decoded one record; active counts
required no record decoding. These are fixture measurements, not production
throughput guarantees.

Pages still use live offsets across requests. Concurrent changes may shift later
pages; Splunk refuses detected overlaps, gaps, inconsistent totals and truncation
but does not obtain a transactional multi-request snapshot. Background observation
polls and workspace analytics still read retained assessment records. SSE hints
avoid per-connection full-workspace decoding; they are not evidence digests.

Observer checkpoints preserve changes since the last successful poll across a
restart. They cannot reconstruct transient changes that appeared and disappeared
while the daemon was offline. Producer connections remain assertions tied to
current confirmed finding evidence, distinct from operator-reviewed paths and
independently verified exploit chains. Legacy recorded connections are retained.

Shared OSS SDK launch correlation still uses its documented snapshot/session/time
contract. Jenkins' trusted root-session relay is separate; this run does not
claim that stronger producer binding for the shared SDK.
